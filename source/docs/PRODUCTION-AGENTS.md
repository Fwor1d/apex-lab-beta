# APEX LAB — правила разработки

- Объяснения, интерфейс и документация для пользователя — на русском. Идентификаторы и код — на английском.
- Phase 5: `apps/platform/` — главная и shared shell; `apps/browser-telemetry/` — основной браузерный анализ и генерация лёгкой reports route; `apps/mobile/` — независимый учебный Trainer; `apps/desktop/` — необязательный Python/Streamlit oracle. Runtime production — только static `dist/`; Python не требуется пользователю.
- Сначала завершать и проверять мобильную основу. Не усложнять 3D до работоспособности вида сверху.
- Не выдавать синтетические данные, схемы, эвристики или длительность анимации за телеметрию, физику LMU либо прогноз времени круга.
- Каждая будущая трасса должна содержать происхождение геометрии, единицы и статус точности. Настройки привязаны к повороту.
- Состояние воспроизведения имеет один источник истины. Машина, курсоры и показания используют один и тот же нормированный прогресс.
- Не передавать телеметрию в сеть. Не добавлять аналитику, CDN, внешние шрифты, аккаунты и секреты. Публикация требует явного разрешения пользователя.
- Прежде чем писать DuckDB-импортёр, прочитать официальную документацию LMU и исследовать схему реального файла в режиме read-only. Не угадывать имена таблиц, единицы или отсутствующие каналы.
- Отсутствие канала обозначать как отсутствие данных; гипотезы отделять от измерений.
- Изменения проверять `npm test`, `npm run test:e2e` и `npm run check:security`. При изменении визуализации осмотреть скриншоты.
- WebKit-тесты не заменяют проверку физического iPhone. Фиксировать непроверенные условия в `docs/TESTING.md`.
- После изменения статических ресурсов обновлять версию кеша и список `ASSETS` в `apps/mobile/sw.js`.
- Для статического хостинга использовать относительные пути; приложение должно работать в подпапке.
- Не изменять `reference/v0.2/`: это исходный архив. Тестовые артефакты, зависимости и персональные файлы не включать в Git.
- Не выполнять бесконечные или повторные проверки после успешного прогона без новых изменений либо конкретной причины.
- Геометрический источник Sebring — `data/sebring/centerline.geojson`; генерировать ES module через `npm run build:geometry`. Сохранять исходные координаты, атрибуцию OSM/ODbL и provenance. Не растягивать осевую линию до объявленной длины LMU.
- Расстояния относятся к осевой линии; приблизительный коридор и границы учебных окон не выдавать за лимиты трассы. Не переносить пит-лейн IMSA в WEC без отдельной проверки.
- Для положения и курса во всех камерах использовать `vehiclePose`; не вводить отдельный прогресс либо ориентацию камеры.
- Пользоваться `PRODUCT.md`, `DESIGN.md` и проектным официальным `.agents/skills/impeccable/SKILL.md` при изменении UI. Автоматические hooks Impeccable не включены; не включать их без проверки. Детектор не заменяет осмотр фактических CSS и снимков.
- Функциональный текст не меньше 11 CSS px; основные пояснения 14 px, подписи графиков 12 px. Проверять размеры текста после CSS-каскада, а не только исходные декларации.

- Учебное ядро — `src/driving-profile.js`, планируемая линия — `src/trajectory.js`. Скорость интегрируется по длине пути; целевая скорость апекса не задаёт рассчитанный профиль. Не возвращать искусственные `exitSpeed`/12 секунд или оценку близости к defaults.
- Все допущения и пороги риска документировать в `docs/DRIVING-MODEL.md`. ABS/TC — концептуальное ограничение действий; снос/занос не считать рассчитанной траекторией. Недостижимую конфигурацию объяснять явно.
- Контракт `profile-contract.js` различает educational/synthetic/telemetry-derived. Missing = null; единицы и источник обязательны. Portimão/McLaren не совместим с эталоном Porsche/Sebring. Наличие JSON SHA-256 не доказывает подлинность исходного DuckDB.

- Desktop: `apex_telemetry/lmu.py` поддерживает исследованную LMU Version 1; справочник и ограничения — `docs/LMU-SCHEMA.md`. Не переносить предположения этой версии на неизвестные схемы. CarName — записанное название/ливрея, не гарантированный идентификатор модели.
- Доступ к DuckDB — только через `readonly`, внешние источники/расширения отключены. Из UI вызывать фиксированные функции через `run_isolated`; `app.py` должен оставаться безопасным при импорте дочерним процессом Windows spawn.
- `Lap Time > 0`, последовательность Lap, покрытие, согласование часов и In Pits проверяются отдельно. `Best LapTime` может быть перенесённым состоянием. Ноль времени не доказывает конкретную причину незачтённости. Не смешивать файлы по совпадению имени машины.
- Фильтр времени/покрытия/пит-состояния не является независимой спортивной сертификацией LMU. Без отдельного ValidLap/penalty не объявлять все нарушения исключёнными.
- Каналы без timestamps синхронизируются только при подтверждённых частотах, плотных rowid и числе строк; хранить допущение и неопределённость. Сравнение кругов — по `Lap Dist`, никогда по номеру строки. Пропуски не соединять, плато отключает дельту.
- Синтетические SQL-fixtures маркировать `APEXDataKind=synthetic` в metadata. Экспорт JSON не подтверждает подлинность файла/валидность круга; source_verified не десериализуется из него.
- Реальные файлы и подробные результаты хранить в `personal-data/`, без Git. В отчётах/скриншотах исключать DriverName, SteamID, абсолютные личные пути и исходные профили. Локальный запуск — `apps/desktop/run.py`, localhost и gatherUsageStats=false.
- Проверки Desktop: `.venv/bin/python -m pytest -q apps/desktop/tests`, Ruff с `--config apps/desktop/pyproject.toml`, `npm run test:desktop:e2e`. Реальная интеграция opt-in через `APEX_LMU_ARCHIVE` и `APEX_REAL_BROWSER=1`; отсутствие личных данных на чужой машине — явный skip.

- Browser: официальный `@duckdb/duckdb-wasm@1.32.0`, single-thread eh/mvp, assets локальны и закреплены lock/integrity. Сборка `npm run build:browser`; проверять `/apex-lab/` без COOP/COEP. Не вводить CDN, OPFS или backend ради удобства.
- Native browser импорт — FileHandle + фиксированный READ_ONLY ATTACH, дорогие операции в Worker, отключённые extensions/external access, bounded deadlines и явное завершение. Не подменять native-тест экспортом JSON и не изменять Python-оракул ради совпадения.
- Browser quality повторяет Python на проверенных исходниках. Missing/contradictory metadata и неизвестное InPits запрещают автоматическое двухкруговое сравнение. Pit/partial должны оставаться отдельно; guards неизвестных входов документировать отдельно от эквивалентности шести записей.
- `report-worker.js` не загружает DuckDB/Wasm; export whitelist, source_verified из JSON не доверять. Не смешивать data kinds или car/track/layout/session; неизвестная модель не становится Porsche/McLaren. JSON и native report не являются спортивной сертификацией.
- После изменения browser static resources обновлять версию/ASSETS `apps/browser-telemetry/sw.js`. Только явный программный allowlist-кеш, никакой личной базы/отчёта. Проверять сеть context-level включая Workers/SW; blob-read не считать upload. Meta CSP документа не называть CSP sandbox Worker.
- Browser проверки: `npm run test:browser:unit`, `npm run test:browser:e2e`; opt-in `APEX_REAL_BROWSER=1` и приватный `APEX_BROWSER_ORACLE`. Полноточный оракул генерирует `scripts/browser-oracle.py` в personal-data/, Python engine остаётся независимым. Privacy/результаты/скриншоты — без DriverName/SteamID/личных путей.

- Сборка `npm run build -- --base=/apex-lab/` (либо `/`) и `npm run check:build` обязательны перед выпуском; Pages workflow только ручной, deploy=false по умолчанию. Не push/deploy без разрешения.
- Landing/Trainer/Reports не загружают Wasm; native офлайн подготавливается отдельным действием, один selected bundle. Cache scope раздела; fixed GET allowlist, никаких personal files. Обновлять home/browser SW при изменении ресурсов.
- `findings-view.js` только presentation: не менять численные доказательства/quality policy ради UI. Synthetic kind виден рядом с источником и в findings. Записанная Lap Time difference отдельно от distance-end delta.
- Phase 5 проверки: `test:browser:unit`, `test:browser:e2e` с private oracle, `test:platform:e2e`, Python regression, `check:build`. Приватные benchmark/test artifacts — только personal-data; публичные screenshots без идентификаторов водителя.

- Phase 6: `coaching-engine.js` — дополнительный детерминированный слой, `coaching-types.d.ts` — схема1.0.0, `DIAGNOSTIC-POLICY.md` — пороги/границы. `analysis.js`, importer и Python oracle не менять ради более выразительного совета; legacy findings сохранять отдельно.
- Only `time-region` finding owns measured timeImpactS; section повторяет его для группировки, не дополнительная потеря. Technique impact=null. Не соединять gaps/плато, не приписывать причину по минимуму скорости/рулю.
- Onset/pickup в пределах sampling bound или с неизвестным bound → inconclusive. Bound не является доверительным интервалом. Steering Pos — normalized signed input. События с неизвестной семантикой не создают физический диагноз; `LMU-EVENT-SEMANTICS.md` обязателен перед расширением.
- `extensions.coaching` в apex-report/1.0 — ограниченный снимок, не доверенный диагноз; пересчитывать из профилей в report Worker. Native/report Workers сериализуют отчёт один раз и проверяют UTF-8≤32МиБ; UI скачивает готовую строку. Не добавлять main-thread аналитические обходы.
- Consistency требует ≥3 distinct compatible eligible lapId и явно pit=false; вывод описательный. Не импортировать отсутствующую выборку из JSON snapshot.
- Артефакты suites разделены: test-results/mobile, browser-telemetry, desktop; platform Phase6 — personal-data/reports/phase-6-platform/e2e. Не очищать общий родитель при параллельных запусках. Тестовые thresholds/сценарии не ослаблять.
- Hardware release blockers — docs/RELEASE-BLOCKERS.md; автоматические Chromium/WebKit на Mac их не закрывают. Публикация и Phase7 требуют отдельного задания.

- Phase 6.5: исходный Trainer — default `original`; `TrainerState.visualization` — только presentation. Все варианты используют тот же progress/vehiclePose; setVisualization не паузит и не сбрасывает view/settings. Не удалять прежние top/cockpit/chase.
- `full-track-view.js` — ленивый Canvas presentation, flat3d только экранная проекция z=0. Толщина линии в пикселях не является шириной трассы; учебные наложения не телеметрия. Цвет линии согласовывать с существующей легендой.
- `map-context.js` — справочный каталог, не импортёр и не регистрация Lap Dist. Algarve GPS около60N/0E: относительная метрика исследована, точная привязка withheld по docs/POSITION-VALIDATION.md. Не включать реальные пространственные ghost/heatmap/yaw/elevation до независимой валидации. Неизвестный layout не заменять Sebring/GP.
- Новые UI-переключения проверять на pageerror, aria-pressed, завершение loading и сохранение полного состояния, а не только видимость Canvas. При WebKit select измерять фактический 44px target. Не ослаблять CSP ради оформления нативных контролов.

- Phase 6.6: `apps/mobile/src/workspace-ui.js` — presentation для Trainer/Telemetry/Reports; не переносить в него importer, quality или Coaching Engine calculations. Перемещать прежние DOM-узлы, не дублировать состояние. Слои/сворачивание не сбрасывают progress, playing, A/B, zoom и findings.
- Центральная SVG-схема анализа — ось измеренного Lap Dist, не географическая карта. Range highlight читает engine fields; нельзя присваивать ему новую потерю времени. Очищать ссылки на comparison при reset; отключать observers при pagehide. Независимые графические слои не создают отсутствующих каналов/пространственных данных.
- Мобильные панели имеют отдельную компоновку: playback сразу под сценой, разбор перед графиками, настройки ниже. Проверять итоговый flex order, а не только порядок DOM. Область касания мини-карты ≥44px после масштабирования SVG; canvas/plot CSS-высоты должны совпадать.
- Engine Impeccable0.1.14 установлен в стандартный user cache; skill4.5.2 и launcher не заменены. Hooks явно disabled в .impeccable/config.json. Detector не считать утверждением достоверности телеметрии и не подавлять правила ради чистого отчёта.
- Дополнительный polish6.6: Focus Mode обязан оставлять playback в центре; hide/show панели не влияет на playing, progress или сигналы. Сброс слоёв обрабатывает только `input[data-layer]`, не hidden-input выбора heatmap. Fit исходного вида включает обе линии и коридор, сохраняет uniform scale/метры; тестировать containment и HUD/caption reserves, не только совпадение формулы.

- Phase 7: package-acceptance/release-probe — dev-only helpers; runtime остаётся статическим. Отчёты/пакеты/стресс-файлы только в personal-data. Powershell launcher loopback GET/HEAD, без firewall/admin/upload; его доступность на Windows не доказывается Mac-тестом Node-сервера.
- Длительные записи не обходят GPS500000/native256MiB guards. READY FOR DEVICE ACCEPTANCE не означает READY FOR PUBLICATION. Аппаратные результаты и secure-origin/PWA upgrade закрывать только фактическим протоколом DEVICE-ACCEPTANCE.

- Track Atlas: `data/track-atlas/layouts.json` → `scripts/import-atlas.py` → runtime manifest/GeoJSON. Schema1.0.0, source SHA/license/provenance обязательны; resolver точный track+layout, отсутствующие варианты не подменять GP. Все текущие новые контуры reference-only. `FullTrackView` общий renderer; pan/zoom — только presentation. Нельзя включать spatial telemetry overlays без независимой регистрации/offset/residuals.
- Public beta разрешена только в отдельном `Fwor1d/apex-lab-beta` со статическим `dist/`; основной исходный Git не публиковать/не связывать с этим remote. Перед каждым push artifact: clean build/check:build, private/secret/license review. DNS/custom domain и изменение видимости исходного проекта не разрешены. Hardware blockers остаются открытыми.

- Phase8: `atlas.js` — один registry/capability API; `CIRCUITS` mobile — только специальные сценарии, не инвентарь. `layout-validation.json` обязателен для shared/новых геометрий; изменения generated manifest воспроизводить importer. Shared grid/pit shape ≠ validated SF/LMU registration.
- `lessons.js` — общие educational упражнения с отдельными assumptions, не настройка Porsche на чужой трассе. Кешсостояний≤16, ключ включает layout/topic/window/geometry basis; render cache учитывает path identity. Только смена view сохраняет playing; смена track/exercise паузит без потери прежних параметров.
- При exploring не показывать старые сигналы/метки/пояснения Sebring. При неизвестном layout не подставлять GP. Атрибуция ODbL доступна и в generic lesson, native context не меняется ручным picker.
- Offline: shell-query разрешён только для navigation к фиксированному route shell; в cache хранится canonical URL без параметров. Assets остаются exact allowlist; addAll нормализовать/deduplicate, никогда не кешировать user data. Не скачивать все geometry при Trainer/PWA startup.

- Phase9: `position-source.js` — отдельный readonly адаптер реальных positional channels, не замена importer. `position-mapping.js` schema1.0 rigid rotation/translation, scale=1; holdout остатки не являются доказательством CRS. Spatial overlays разрешать только при независимых reviewed anchors/layout/geometry uncertainty/metric validation; JSON flags не принимаются. Все текущие real mappings reference-only; SF/uncertainty=null. Численные результаты сохранять privately, документация — `SPATIAL-MAPPING-VALIDATION.md`.
- `analytics-extended.js` — дополнительный Worker слой без изменения oracle/delta/Coach thresholds. Интеграл brake ratio·s не давление; joint release/steering не физический trail-braking диагноз.50м microSegments — альтернативная детализация, не складывать с Coach time-regions; technique timeImpact=null. Recurring≥3 distinct compatible eligible/pit=false laps, не объединять сессии.
- `map-layers.js`/OSM context — реальные sourced polygons/ways, bounded/lazy/render culling; не буферизовать ось в выдуманную ширину. Пит-пути OSM не подтверждают LMU pit/SF/track limits. `context-index.json` хранит sourceSHA/license/omissions; all18 geometry не скачивать автоматически. Canonical context assets находятся в telemetry/data, Reports не дублирует их. Hooks Impeccable остаются disabled; release/DNS/private repo не менять.

- Phase10: `native-trajectory.js` — отдельный локальный допуск, не geographic `position-mapping.js`. Исходные 10Гц-точки в фиксированной кандидатной плоскости, без ICP/OSM/per-lap fit/сглаживания/замыкания. Clock/rowid/unit guards сохранять. Native validation schema1.0.0; любой jump запрещает путь, missing разрывает связи; пороги и NumPy evidence — SPATIAL-MAPPING-VALIDATION.
- `NativeView` и `MapContext` делят один `FullTrackView`/Canvas listener set. Native маркеры круглые, не yaw; A/B только same recording/context/quality/frame и shape check. Временной cursor A→исходная точка→LapDist→пять графиков, B distance-matched; пропуск не интерполировать. OSM-specific controls скрыты в local mode. Coach/50м highlight не создаёт новое timeImpact.
- Native coordinates не сериализованы в apex-report1.0. Старые/новые JSON остаются distance-only, без Wasm и без доверия к spatial flags. Сохранять явный unavailable state. Private coordinate arrays/исследования/benchmarks только personal-data; screenshots без идентификаторов. Публикация этой фазы не разрешена.

- Phase11: `apps/platform/ui/` — только presentation; оригинальные React Bits CometDial/SpotlightCard и provenance закреплены. Не менять их геометрию/spring ради имитации. React/DOM/Motion — один lazy bundle, Anime отдельно; JSX/generated bundles не попадают в runtime как исходники/репозиторий соответственно. Worker stages без измеримой доли остаются indeterminate, без фиктивных процентов. Motion preference хранит только `apex-motion`, не влияет на playback/progress/formulas. Сохранять hidden/BFCache cleanup и generation guards; не расширять CSP для оформления native controls. Preview Sebring генерируется из исходного GeoJSON с uniform scale/источником, не является LMU registration.
