# LMU Version 1 — исследованная схема и каналы

Публичная выдержка из проверенного адаптера LMU Version 1. Идентификаторы, даты и агрегаты частных записей исключены; исходный отчёт сохранён локально. Эти соответствия не распространяются автоматически на неизвестные версии.

До написания адаптера изучены [официальное описание LMU Telemetry Recording](https://guide.lemansultimate.com/hc/en-gb/articles/14524956311695-Telemetry-Recording) и настоящие SQL-каталоги в read-only. Официальная страница описывает выбор каналов/частот, но не заменяет словарь таблиц и единиц конкретного файла.

## Структура

Во всех шести файлах одна структура: **109 BASE TABLE**, без представленных foreign keys/constraints, 66 каналов и 40 событий. `config.json` содержит 66 `Channels` и 40 `Events`; наличие определения не доказывает наличие наблюдения/единицу. Единицы берутся из каталогов базы.

| Таблица | Реальные колонки | Назначение |
| --- | --- | --- |
| `metadata` | `key VARCHAR`, `value VARCHAR` | 12 пар, включая Version, DriverName, SteamID, RecordingTime, SessionTime, SessionType, TrackName, TrackLayout, WeatherConditions, CarName, CarClass, CarSetup |
| `channelsList` | `channelName VARCHAR`, `frequency INTEGER`, `unit VARCHAR` | Имена native каналов, номинальная частота, единица значения |
| `eventsList` | `eventName VARCHAR`, `unit VARCHAR` | Имена событий и единица значения; частоты нет |
| Канал со скаляром | `value` | FLOAT/DOUBLE/BOOLEAN и другие реальные типы, **без timestamp** |
| Канал с четырьмя компонентами | `value1…value4` | Например, шины/колёса; порядок компонентов не подменяется догадкой |
| Скаляровое событие | `ts DOUBLE`, `value` | Состояние/изменение на игровых часах |
| Векторное событие | `ts DOUBLE`, `value1…value4` | TyresCompound/WheelsDetached; перечисляется, не нормализуется в MVP |

Полные каталоги и статистика частных файлов не публикуются. Частота событий on-change не превращается в регулярную сетку; постоянное значение не доказывает поддержку системы.

## Метаданные автомобиля, трассы и сессии

- `Version=1`. CarName является записанным именем/ливреей, а не надёжным идентификатором модели; CarClass и layout нельзя выдумывать.
- RecordingTime содержит дату записи, SessionTime — игровые часы; персональные значения не приводятся.
- SessionType, RecordingTime и SHA-256 исходника задают изолированную запись. Файл, возобновлённый с того же игрового времени, не объединяется автоматически с другим.
- DriverName хранится и показывается только локально по отдельному выключенному по умолчанию переключателю. SteamID со значением 0 не используется как идентификатор пилота.

## Проверенные основные соответствия

| Native таблица | Тип value | Каталог | Нормализованное поле | Преобразование |
| --- | --- | --- | --- | --- |
| `GPS Time` | DOUBLE | 100 Гц, s | `timeS` | Игровые секунды минус установленное начало круга; не wall-clock |
| `Ground Speed` | FLOAT | 100 Гц, km/h | `speedMps` | / 3,6 |
| `Brake Pos` | FLOAT | 50 Гц, % | `brake` | / 100 |
| `Throttle Pos` | FLOAT | 50 Гц, % | `throttle` | / 100 |
| `Steering Pos` | FLOAT | 100 Гц, % | `steeringNormalized` | / 100, диапазон −1…1; направление лево/право и угол колёс не выводятся |
| `Lap Dist` | FLOAT | 10 Гц, m | `distanceM` | Без растягивания/переноса нуля; reset и откаты обрабатываются отдельно |

Filtered/Unfiltered варианты остаются отдельными исходными каналами. MVP использует указанные строки, не подменяет их похожими именами. Unknown unit/frequency, неплотные rowid или неправильное число строк отключают конкретный сигнал. Статус `missing` и все его значения — null.

`GPS Latitude/Longitude` имеют единицу deg и реальные меняющиеся значения, но расположены около 60°N/0°, а не Portimão. Origin/CRS не подтверждены, поэтому не строятся WGS84-карта, позиция XY, heading и соответствие именованным поворотам. `Steered Angle` отсутствует. G Force/прочие ускорения и их оси не нормализуются по предположению. Координатные/ускорительные поля переносимого контракта остаются отсутствующими.

`ABS` — BOOLEAN `ts/value`, `TC` — регулярный BOOLEAN канал 100 Гц. ABSLevel, TCLevel, TCCut и TCSlipAngle также присутствуют. Значение сигналов именно как вмешательства/причины потери пока не подтверждено документацией конкретной версии; коучинг ABS/TC отключён. Пустая unit для enum/state не угадывается как угол/процент.

## Часы и частоты

Реальные GPS Time равномерны: шаг 0,01 с, без null, повторов, обратных timestamps и разрывов >3 median во всех файлах. Основные таблицы имеют ровно `ceil(N / (100/f))` строк, где N — число GPS Time; rowid начинаются с 0 и плотны. Поэтому native 50/10 Гц привязаны к каждому второму/десятому отсчёту GPS Time.

**Это восстановленная временная привязка.** В таблицах значений нет собственной проверки фазы/пропущенных кадров. Пара «потеря + дубликат», сохраняющая число строк, не обнаруживается достоверно. Каналы с f=7 не имеют точного делителя 100 и числа строк не равны простой формуле; они только инвентаризируются. Их nominal frequency не выдаётся за независимо измеренную частоту.

`ts` событий согласован с игровым GPS Time и границами Lap; интервалы сравниваются с `Lap Time` в явно указанных секундах. Собственная unit колонки ts в каталоге отсутствует: практическая секундная привязка подтверждается этими совпадениями, а не названием колонки. Это не UTC. Максимальный допуск согласования Lap Time/границ в адаптере — 0,04 с.

Педали/руль/скорость линейно интерполируются на GPS-сетку только между соседними конечными значениями. Gap более `max(0,03 с, 3/f)` не пересекается, экстраполяции нет. Для Lap Dist не интерполируется отрицательный reset. Native частота, исходная единица, метод и ориентир времени `1/f` сохраняются в `channels.*.sampling`. Отсутствующие наблюдения не восполняются моделью.

## Круги и статус

`Lap` — USMALLINT событие; `Lap Time` — FLOAT, unit s; `In Pits` — UTINYINT со значениями 0/1. Состояния событий удерживаются до следующего изменения. `Best LapTime` в начале файла может быть результатом предыдущей записи и не создаёт круг.

Положительный Lap Time, согласованные границы и покрытие дают **круг по рабочему фильтру MVP**. Отдельного ValidLap/штрафного флага нет: это проверка времени/данных, а не независимая сертификация спортивной валидности LMU. Ноль Lap Time означает отсутствие положительного записанного времени; причина неизвестна, off-track не утверждается.

Условия фильтра: завершённый интервал, следующий номер Lap = текущий+1, известное начало, положительное время и согласование ≤0,04 с, начало дистанции <20 м, конец ≥97% наблюдаемого максимума этой записи, известное In Pits без пит-переезда, доступная скорость. 97% — эвристическая проверка покрытия, **не официальная длина/гарантия каждого метра круга**. Время, статус и качество дистанции хранятся отдельно. Малые откаты расстояния создают null до восстановления монотонности, не отменяют записанное положительное время.

Первое Lap-событие означает начало записи, не обязательно круга. Начало гонки Lap 0 восстановлено как `finish − Lap Time` только после подтверждения native reset около этой точки (окно 0,15 с, дистанция <15 м). Такая граница явно отмечена `startDerivedFromLapTime`. Первые/последние неполные сегменты не получают искусственного времени.

## Защита и воспроизводимость

Используется [DuckDB Python read_only](https://duckdb.org/docs/current/clients/python/dbapi.html), SHA-256 до/после, только BASE TABLE, параметризованные фильтры и quoted identifiers. Views/macros из базы не выполняются; внешние источники, autoload/autoinstall, community/unsigned extensions выключены. Отдельный процесс с дедлайном 60 с, DuckDB memory 512 МБ, 2 threads, temp size 0. [DuckDB security](https://duckdb.org/docs/current/operations_manual/securing_duckdb/overview.html) описывает границы этих мер; read-only не является полной OS-песочницей.

Лимиты: база 2 ГБ, ZIP/суммарная распаковка 4 ГБ, 256 элементов ZIP, коэффициент сжатия ≤500, 256 таблиц/каналов/событий, 512 колонок, до 500000 отсчётов часов и 100000 событий на таблицу. Portable profile ≤200000 отсчётов/круг; JSON ≤32 МБ. Неизвестная схема исследуется без автоматического адаптера. Для больших/иных записей требуется отдельная поддержка.

Повторить проверку можно `scripts/audit-lmu.py` из инструкции Desktop. Источники неизменны по SHA-256, подробные результаты остаются в `personal-data/reports/`. Новые версии LMU требуют новой проверки реальных файлов.

## Дополнение Phase9: позиционные каналы

Исследованный контракт: GPS Latitude/Longitude10Гцdeg, GPSspeed10Гцm/s, GPSTime100Гцs/LapDist10Гцm; `position-source.js` — отдельный bounded исследовательский adapter, не новый основной importer. PathLateral/TrackEdge m не превращаются в края полотна без подтверждённой семантики. WorldXYZ/height/YawRate/SteeredAngle в исследованной схеме отсутствуют. Подробности/численная проверка/неизвестный CRS — [SPATIAL-MAPPING-VALIDATION](SPATIAL-MAPPING-VALIDATION.md).

Phase10 уточняет прежний запрет «позиция XY не строится»: он относился к географическому наложению на OSM. Отдельная кандидатная локальная плоскость записанной GPS-пары теперь разрешена после проверки временных связей, метрики, выбросов и common-frame A/B. Мировой CRS, физическая абсолютная точность и yaw всё ещё неизвестны; GPSназвания не доказывают WGS84. Подробнее SPATIAL-MAPPING-VALIDATION, NativeTrajectory/1.0.0. Исходные units/каналы/importer не менялись.
