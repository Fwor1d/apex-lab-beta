# Граница перед Phase 3

Phase 2 предоставляет подтверждённую сессию, стабильные recording/session/lap ID, весь список кругов, их исходные проверки и допустимую пару. Нормализованные профили остаются в existing Worker. Контракт B-oriented tagged cursor и единственный playback owner сохранены.

Phase 3 требует отдельного задания. Планируемые шаги:

1. Подключить исходные `profile`/`compare` действия через тот же source с generation guards и bounded lifecycle.
2. Описать доступность каждого результата отдельно от успешного импорта; gaps, plateau и неизвестные каналы должны разрывать представление, не соединяться искусственно.
3. Использовать исходное сопоставление по Lap Dist и единицы m/s, m, s, ratio, signed normalized steering. Не создавать анализ по номеру строки.
4. Построить B-time ↔ distance mapping только из проверенных профилей. Никакого второго requestAnimationFrame clock, синтетических 5000 м или деления дистанции на полное Lap Time.
5. Записанная разница Lap Time B−A и delta на общей валидной дистанции — разные величины. Положительное B−A означает более медленный B.
6. Проверить независимый Python oracle, quality guards, cancel/replacement, границы пропусков, responsiveness и отсутствие сетевой передачи.

Карта, события, coaching и отчёт не становятся доступными автоматически после compare. Пространственный допуск native-trajectory и географическая регистрация — отдельные вопросы; текущий descriptor не обещает CRS/yaw/track limits. Учебный Driving Lab не получает физическую модель автомобиля из CarName.

Запрещено для удобства UI менять существующие importer/analysis/quality/Coach/trajectory/export thresholds. Нужен внешний адаптер и тестируемое представление исходного результата. Публикация и следующие фазы требуют своего явного задания.
